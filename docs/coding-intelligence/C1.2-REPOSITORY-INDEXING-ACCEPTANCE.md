# C1.2 — Repository indexing, project understanding and dependency analysis

**Status: VERIFIED-CLOSED — supported baseline**

## Scope delivered

- Deterministic, bounded repository indexing with language classification through the extensible adapter registry.
- Read-only workspace snapshot collection through `snapshot::collect_snapshot` and integrated `snapshot::analyze_workspace`.
- Canonical-root traversal, symlink/non-regular-file rejection, common generated/vendor directory exclusions, literal root `.gitignore` handling, deterministic ordering, and file-count/per-file/aggregate-byte/depth limits.
- Manifest/project recognition for Cargo, npm, Python, Go, Maven, Gradle, Composer, CMake and Ruby.
- Declaration extraction for supported Cargo, npm, Python, Go and Ruby manifest patterns.
- Lockfile package records and dependency references for Cargo.lock, package-lock.json/npm-shrinkwrap.json and composer.lock, including available source and checksum/integrity metadata.
- Unsupported syntax and unsupported lockfile formats are explicitly marked partial; the index does not claim complete dependency coverage where an adapter is absent.
- Repository data is treated as input data. No manifest scripts, package managers, compilers or arbitrary repository commands are executed.

## Explicit limitations

- pnpm, Yarn, Poetry, Pipenv, Go checksum and Ruby lockfile formats are recognized as lockfiles but remain PARTIAL until dedicated parsers are added.
- Maven, Gradle and CMake manifest dependency extraction remains PARTIAL.
- Dependency vulnerability/advisory lookup, registry resolution, license policy evaluation and automatic remediation are NOT IMPLEMENTED.
- Lockfile dependency references are preserved as evidence; this increment does not claim a fully normalized cross-ecosystem transitive graph.
- The filesystem collector is read-only and bounded, but is not an OS sandbox or a race-free hostile-filesystem boundary.

## Governance

C1.2's bounded indexing and supported-format analysis baseline is verified closed.
