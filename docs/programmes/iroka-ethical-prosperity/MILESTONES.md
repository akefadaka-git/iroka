## Daily progress report format

Each daily report must include:

1. **Executive status:** overall status and evidence-backed completion percentage.
2. **Repository snapshot:** current main SHA, programme branch/PR SHA, inspected PRs and workflow evidence.
3. **Phase/milestone:** active phase, milestone status, completed checklist items and remaining items.
4. **Changes since previous report:** commits, files, PRs, tests and workflow outcomes.
5. **Blockers and risks:** unresolved technical, governance, security, access or evidence issues.
6. **Schedule:** planned week versus evidence-backed actual progress; explain slippage.
7. **Next step:** one specific next action, its dependency and whether it is already authorized.
8. **Governance boundary:** explicitly state that no merge, deployment, production activation or authority expansion occurred unless separately authorized and evidenced.

## Status semantics

- NOT STARTED: no evidence-backed work begun.
- IN PROGRESS: work is underway.
- BLOCKED: a dependency or approval prevents progress.
- PARTIAL: some acceptance criteria are met.
- PASS: defined tests and evidence meet the stated requirement.
- VERIFIED-CLOSED: evidence reviewed and closure established.
- UNRESOLVED: material issue remains.
- NOT RUN: test/check not executed.
- UNKNOWN: evidence unavailable or insufficient.

## Schedule control

The 27-week sequence is not a deadline that overrides quality gates. When a phase is blocked, downstream target windows move accordingly. Never mark a milestone complete solely because its target week has passed. No A3 implementation begins without the applicable A1/A2 approval and explicit implementation authorization. A5 always remains separately authorized.
