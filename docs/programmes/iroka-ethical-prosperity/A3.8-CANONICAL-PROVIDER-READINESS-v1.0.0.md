## 1. Purpose

A3.8 requires exact-provider binding and cross-domain adversarial verification. This record distinguishes capabilities that already exist from adjacent capabilities that are still missing. It prevents a credential from being mistaken for a content approval, an Owner approval from being mistaken for an organization delegation, or a decision audit stream from being mistaken for a memory lifecycle stream.

## 2. Existing providers and their exact semantics

| Provider | Available capability | Does not prove |
|---|---|---|
| G01 | Ed25519 credential verification, trusted issuer/key snapshots, exact audience and validity, fail-closed revocation | Reviewer designation or approval of a specific record |
| G02 | Direct Owner-signed exact-scope approvals, revocation and replay protection; tenant membership | Organization-scoped delegation or reviewer authority |
| G11 | Append-only, hash-chained decision audit | Memory lifecycle events or cross-database atomicity |

These existing capabilities are reusable only within their documented contracts.

## 3. Blocker A — G01 reviewer-proof verifier

The inspected G05 integration port G01ReviewerProofAuthority is an interface, not a concrete G01-owned verifier. The missing verifier must bind:
- current reviewer principal to the currently designated signing key;
- canonical signing bytes and a dedicated signing-domain separator;
- tenant, organization, reviewer, designation version, memory ID, record version, content digest, purpose and classification;
- proof validity, replay protection and current credential/key revocation at proof use.

A G01 credential authenticates a principal but does not prove that the principal approved a specific record. A G02 Owner approval is not a substitute. Until the G01-owned verifier exists, reviewer approval remains denied.

## 4. Blocker B — G02 organization-scoped delegation

The inspected Kernel security store contains tenant membership and policy/revocation state, but no canonical organization-delegation registry or designation/revocation action. Global capability and tenant membership do not establish an organization role.

The authoritative organization source/provider and its governance owner have not been identified in the inspected repository evidence. A future provider must bind and revalidate the exact versioned delegation tuple, including tenant, organization, actor, delegation ID/version, action and reviewer scope, and must specify its consistency/linearization behavior.

This programme must not invent a second organization-authority registry or accept a caller-asserted role.

## 5. Candidate G11 memory-lifecycle adapter

Separate G05 PR #43 adds a versioned, content-free G11 memory lifecycle event stream and a G05 outbox adapter. Its exact head 84b56386879928d28040d0a2c4e502efd1b2ae2c passed GitHub Actions run [42820878358](https://github.com/akefadaka-git/iroka/actions/runs/42820878358).

PR #43 is still OPEN, DRAFT and UNMERGED, based on a separate G05 branch. It is therefore a candidate integration, not an already integrated dependency of this programme. Its design uses a durable outbox and idempotent delivery; it does not claim a distributed transaction or multi-node consistency.

The G11 memory lifecycle stream is separate from the existing G11 decision audit stream. Neither may be overloaded to represent the other.

## 6. Safe implementation boundary

- Reuse G01 credentials/revocation, G02 Owner approval and G11 decision audit only for their established semantics.
- Keep reviewer approval and organization-scoped durable activation fail-closed until canonical providers are implemented and independently tested.
- Do not add duplicate identity, reviewer, consent, delegation, memory or audit registries.
- Do not treat an unmerged branch as a canonical integrated provider.
- Preserve the A2 VERIFIED-CLOSED baseline and its open decision gates.

## 7. Exit criteria

A3.8 may be marked implemented only after:
1. G01 supplies the reviewer-proof verifier and adversarial tests for exact scope, key binding, signature, expiry, replay and revocation.
2. G02 supplies an Owner-governed organization-delegation source/provider and adversarial tests for exact tuple, version, revocation and consistency.
3. The G05/G11 memory lifecycle adapter is reconciled with its canonical base, tested on the intended integration line and reviewed for outbox recovery/idempotency.
4. Cross-domain tests prove fail-closed behavior when any provider is missing, stale, revoked, unavailable or inconsistent.
5. Independent A4 review separately assesses the resulting trust boundaries.

A3.8 remains PARTIAL until these exit criteria are satisfied. This record does not authorize merge, production keys, real user/community data, durable memory activation, protected execution, A4 closure or A5 deployment.
